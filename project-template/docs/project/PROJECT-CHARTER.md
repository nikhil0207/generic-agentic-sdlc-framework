# Project Charter

## Problem Statement

Describe the business/problem context and why change is needed.

## Objectives

State measurable objectives.

## Stakeholders

Identify decision-makers, users, operators, and external parties relevant to scope.

## Current State

Document the current process/system and evidence from the existing repository or source material.

## Desired State

Describe the target outcome without prematurely prescribing implementation details.

## Scope

List what the project/change includes.

## Out of Scope

List explicit exclusions.

## Constraints

Document technology, security, regulatory, schedule, integration, budget, deployment, or operational constraints.

## Assumptions

List assumptions requiring validation.

## Dependencies

List upstream/downstream systems, teams, environments, or decisions.

## Risks

| Risk ID | Description | Likelihood | Impact | Mitigation | Owner/Decision |
|---|---|---|---|---|---|

## Success Criteria

Define measurable success criteria.

## Open Questions

List unresolved questions that materially affect requirements or architecture.
